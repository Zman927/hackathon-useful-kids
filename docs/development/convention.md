# 커밋 컨벤션

형식: `<type>: <내용>`

| Prefix | 의미 | 예시 |
|---|---|---|
| `feat:` | 새 기능 추가 | `feat: 기자재 목록 조회 API 추가` |
| `fix:` | 버그 수정 | `fix: 재고 0일 때 승인 안 막히던 문제 수정` |
| `refactor:` | 동작 변화 없는 코드 구조 개선 | `refactor: rentals 라우터 서비스 계층으로 분리` |
| `docs:` | 문서만 변경 | `docs: API 명세서에 반납 엔드포인트 추가` |
| `style:` | 포맷팅, 세미콜론 등 코드 의미에 영향 없는 변경 | `style: 들여쓰기 정리` |
| `test:` | 테스트 추가/수정 | `test: 대여 승인 API 재고 부족 케이스 추가` |
| `chore:` | 빌드, 패키지, 설정 등 그 외 잡일 | `chore: requirements.txt에 python-multipart 추가` |

## 원칙

- 한 커밋 = 한 가지 변경. 여러 타입이 섞이면 커밋을 나눈다.
- 제목은 무엇을 바꿨는지 한 줄로 읽힐 정도로 구체적으로 쓴다. `fix: 버그 수정` 같은 제목은 지양.
- 완성될 때까지 기다리지 말고, 작업하다 끊기는 지점마다 커밋한다.
- **하루 최소 한 번은 push.** 다른 사람이 이어받을 수 있는 상태를 유지하는 게 목적.
