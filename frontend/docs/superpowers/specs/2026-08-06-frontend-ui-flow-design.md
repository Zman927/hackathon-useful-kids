# 기자재 대여 시스템 - Frontend 5페이지 UI 흐름 설계

## 배경

공학관 학과별 기자재 대여 시스템의 프론트엔드(React + Vite + React Router). 기존 4개 페이지(Home, EquipmentDetail, Rental, MyPage)는 모두 타이틀만 있는 플레이스홀더 상태였다. 이번 설계는 코드 작성 없이, 학생 사용자 기준으로 5개 페이지(Login 추가)의 목적 / 사용자 행동 흐름 / 필요 UI 요소 / 페이지 간 이동 관계를 정의한다.

## 네비게이션 아키텍처

**상시 노출 글로벌 네비게이션** 방식을 채택한다. Login을 제외한 모든 페이지 상단에 고정 헤더(로고/Home 링크 + 학과 선택 드롭다운 + 마이페이지 아이콘)를 두어, 사용자가 대여 신청 흐름 중이 아니어도 언제든 Home과 MyPage로 이동할 수 있게 한다.

대안으로 검토했던 단계형 플로우(Wizard, 헤더 없이 선형 이동만 허용)는 마이페이지 접근성이 떨어져 기각했다.

## 페이지별 설계

### 1. Login

- **목적**: 학번+비밀번호를 DB와 비교하여 사용자를 인증. 회원가입은 이번 범위에서 제외(계정은 사전에 존재한다고 가정).
- **사용자 행동 흐름**: 앱 진입 → 학번 입력 → 비밀번호 입력 → [로그인] 버튼 → Home 이동. 불일치 시 오류 메시지 표시.
- **필요 UI 요소**: 서비스 로고/타이틀, 학번 입력 필드, 비밀번호 입력 필드(마스킹), [로그인] 버튼, 인증 실패 안내 텍스트.
- **페이지 간 이동**: 로그인 성공 → Home. (진입점이므로 뒤로가기 대상 없음)

### 2. Home

- **목적**: 학과를 선택하고 해당 학과의 대여 가능 기자재 목록을 조회.
- **사용자 행동 흐름**: Home 진입 → 헤더에서 학과 선택 → 선택 학과의 기자재 목록 표시 → 카드 클릭 → EquipmentDetail 이동.
- **필요 UI 요소**: 전역 헤더, 기자재 카드 리스트(이미지/이름/카테고리/대여가능 뱃지), 학과 미선택 안내 문구, (선택) 카테고리·검색 필터.
- **페이지 간 이동**: 헤더 마이페이지 아이콘 → MyPage. 카드 클릭 → EquipmentDetail(기자재 id 전달).

### 3. EquipmentDetail (기자재 상세)

- **목적**: 선택한 기자재의 상세 정보를 확인하고 대여신청 여부를 결정.
- **사용자 행동 흐름**: Home에서 진입 → 상세 확인 → [대여신청] 버튼 → Rental 이동. 대여불가 상태면 버튼 비활성화.
- **필요 UI 요소**: 전역 헤더, 기자재 이미지/이름/카테고리/설명, 대여가능 여부·재고 상태 뱃지, [대여신청] 버튼(비활성화 조건 포함), 뒤로가기(← 목록으로) 링크.
- **페이지 간 이동**: [대여신청] → Rental(기자재 id 전달). 뒤로가기 → Home. 헤더 마이페이지 아이콘 → MyPage.

### 4. Rental (대여 신청)

- **목적**: 특정 기자재에 대해 대여 기간·수량·사유를 입력해 신청서를 제출.
- **사용자 행동 흐름**: EquipmentDetail에서 진입(대상 기자재 요약 표시) → 대여기간(시작일~반납일)/수량/사용목적 입력 → [신청하기] → 완료 안내 → MyPage 이동.
- **필요 UI 요소**: 전역 헤더, 신청 대상 기자재 요약(읽기전용), 대여기간 date picker, 수량 입력(스텝퍼), 사용목적/사유 텍스트 입력, [신청하기] 버튼(필수값 미입력 시 비활성화), 제출 완료 안내(모달/토스트).
- **페이지 간 이동**: 제출 성공 → MyPage(신청 건이 "심사중" 상태로 목록 최상단 표시). 취소/뒤로가기 → EquipmentDetail.

### 5. MyPage (마이페이지)

- **목적**: 내가 신청한 모든 대여 건과 각 건의 진행 상태를 한눈에 확인.
- **사용자 행동 흐름**: 헤더 마이페이지 아이콘 클릭 → 진입 → 상태별 대여 내역 확인.
- **필요 UI 요소**: 전역 헤더, 사용자 정보 요약(학번/이름), 대여 내역 리스트(기자재명/신청일/대여기간/상태 뱃지: 심사중·대여중·반납완료), 상태별 필터/탭, 빈 상태 안내.
- **페이지 간 이동**: 헤더 로고/Home → Home. 하위 상세 이동은 이번 범위에서 제외(선택 사항으로 남김).

## 전체 페이지 이동 관계

```
Login --(로그인 성공)--> Home
Home --(학과 선택)--> Home(목록 갱신)
Home --(카드 클릭)--> EquipmentDetail
EquipmentDetail --(대여신청)--> Rental
EquipmentDetail --(뒤로가기)--> Home
Rental --(신청 완료)--> MyPage
Rental --(취소/뒤로가기)--> EquipmentDetail
[전역 헤더] Home ⇄ MyPage (Login 제외 모든 페이지에서 접근 가능)
```

## 디바이스 타겟

데스크톱 우선(반응형 고려 없이 넓은 화면 레이아웃 기준으로 설계).

## 가정 및 Backend 확인 필요 사항

아래 항목은 이번 설계 범위에서 임의로 가정한 값이며, backend 팀원과 확정 후 값만 맞추면 되는 수준이다. UI 구조 자체를 바꾸는 항목은 아니다.

1. **로그인 방식**: 학번+비밀번호를 DB와 비교하는 방식으로 확정, 회원가입은 범위 제외. 다만 인증 성공 후 토큰 발급 방식(JWT/세션 등)은 아직 미정이라 확인 필요.
2. **기자재 데이터 필드명**: `name`, `imageUrl`, `category`, `availability` 등은 가정한 이름. 실제 API 응답 스키마 확인 필요.
3. **대여 상태값(enum)**: "심사중/대여중/반납완료"는 임의 한글 라벨. 실제 API의 상태 코드(예: `PENDING`/`RENTED`/`RETURNED`) 확인 후 매핑 필요.
4. **학과 목록 소스**: 정적 하드코딩 vs API 조회 여부 미정.
5. **기자재 id 전달 방식**: EquipmentDetail은 기존 라우터상 `/equipment/:id` 사용 중. Rental도 URL 파라미터(`/rental/:id`)로 통일할지, state로 전달할지는 API 설계와 함께 결정 필요.
