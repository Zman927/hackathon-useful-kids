## 프로젝트

공학관 기자재 대여를 디지털화하는 플랫폼. 학생은 학과별 기자재 재고를 조회하고 대여를 신청하며, 조교는 대시보드에서 신청을 승인·반려하고 반납을 처리한다. 기존의 수기 장부와 조교별 파일 관리를 대체하는 것이 목표다.

## 스택

- **프론트엔드**: React
- **백엔드**: FastAPI
- **DB**: PostgreSQL

## 브랜치 전략

- `main` — 통합 브랜치. 시연·제출에 쓰이는 상태.
- `frontend` — 프론트엔드 작업 브랜치. `frontend/` 폴더만 다룬다.
- `backend` — 백엔드 작업 브랜치. `backend/` 폴더만 다룬다.

각자 브랜치에서 작업하고, 기능이 완성되면 `main`으로 머지한다.

## 커밋 메시지 규칙

형식: `[타입] 무엇을 했는지 한 줄`

| 타입 | 의미 |
|---|---|
| `추가` | 새 기능·화면·엔드포인트 등을 새로 만듦 |
| `수정` | 기존 동작·화면·로직을 고침 |
| `삭제` | 파일·코드·기능을 지움 |
| `문서` | README, 주석 등 문서만 변경 |
| `설정` | 패키지 설치, 환경변수, 배포 설정 등 |

예시:
```
[추가] 기자재 목록 조회 화면
[수정] 대여 신청 폼 유효성 검사 버그 고침
[설정] Postgres 연결 환경변수 추가
```

- 거창하게 쓸 필요 없다. **무엇을 바꿨는지 한 줄로 알아볼 수 있으면 충분.**
- 완성될 때까지 기다리지 말고, 작업하다 끊기는 지점마다 커밋한다.
- **하루에 최소 한 번은 push.** 다른 사람이 내 작업을 이어받을 수 있는 상태를 유지하는 게 목적.
